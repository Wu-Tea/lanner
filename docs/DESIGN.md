# 设计说明：如何组织项目认识与协作信息

Project Cognition 通过持续维护项目认识和工作记录，帮助开发者理解当前工作、发现相互影响，并判断整体进展。本文说明这些信息如何组织、由谁维护，以及工作推进时怎样更新。产品目的和第一版范围见 [MVP](MVP.md)。

以下仍是设计提案。本文讨论需要表达的信息和职责，具体字段、存储方式与运行机制尚未定型。

## 一、维护哪些信息

### 项目知识与当前工作

理解项目，需要掌握功能、模块、关键流程、已有能力及其关系。我们将这部分持续维护的认识称为项目模型，将跨任务保存和复用这些认识的长期知识库称为 Base。Base 还保留相关规范、决定、经验、风险和重要未知，并记录来源及适用范围。首次接入时它可以为空，由调查和资料整理逐步建立。

正在推进的工作另有记录。任务说明原始请求、目标、范围、执行者、完成条件、依赖和当前状态；会话记录说明围绕这些任务发生了什么。一个任务可以经历多次会话，一次会话也可以涉及多个任务，两者通过关联保持接续。

项目提供共同的协作范围，其中维护目标、受益者、成功条件和重要约束。需要长期跟踪某项业务或工作时，可以把相关任务归入同一条工作线。工作线按工作目标组织，可以跨越多个模块，同一模块也可以参与不同工作线。

这些概念用于解释信息之间的关系，不要求一开始就创建完整的数据结构。尚未确定的责任人、日期和承诺保持未定。

### 来源、决定与实际结果

资料中的要求、实现中的行为和运行中的结果各有依据。判断当前实现时查看代码和配置；理解业务要求与设计理由时查看已确认的决定；判断哪些行为已经验证时查看测试与运行记录。资料作者的描述和 Agent 的推断也应保留其原有性质。

工作记录保存决定、变动和行动项。决定需要说明由谁在什么范围内确定了什么、为什么这样选择，以及是否替代旧决定。风险记录尚未发生的问题，问题记录已经发生的情况，行动项说明准备如何处理，并保留影响、责任和解除条件。

实际产物与验证依据支持结果判断；其中具有后续使用价值的认识，经过核对后才进入 Base。协调报告引用这些资料，说明某一时点的综合判断，避免再独立维护一套事实。

### 关联分散的信息

项目模型为模块和功能保留稳定标识及别名。会话根据涉及的内容提出标签和关联，帮助找到可能相关的记录。进一步判断相关性时，要核对任务目标、适用范围、具体引用和依赖关系。

标签相同不一定表示工作相关，没有共同标签也不能排除实际依赖。因此，除了标签，还需要表达任务服务于哪个目标、依赖哪些结果、受到什么变更影响，以及哪些产物支持了完成判断。

## 二、谁来维护这些信息

同一个 Agent 在工作中可以切换不同职责。以下五个视角用于明确各自要完成的事情，不要求部署五个常驻 Agent。

| 职责 | 主要工作 |
| --- | --- |
| 理解项目 | 调查结构与流程，整合资料，提出项目模型的修正 |
| 执行任务 | 理解目标和规范，复用已有能力，自主完成工作并提供产物与自查结果 |
| 记录会话 | 提取重要讨论、纠正、决定、工作变化和未完成事项，保留来源 |
| 协调工作 | 汇总相关任务，发现依赖、冲突和资源限制，提出后续协调建议 |
| 核验结果 | 对照目标、规范和依据，检查任务结果、综合判断及准备保留的知识 |

其中，协调工作的职责称为 manager。它需要了解相关工作的整体情况，但不会因为负责汇总就自动获得分派他人、调整共同优先级或承诺交付的权限。

记录参与者身份、Agent 归属和具体执行过程，是为了明确信息来自谁、当时能看到什么，以及获得了哪些授权。多人参与时，某个 Agent 的用户不自动代表全项目。目标、优先级、业务取舍和风险接受由具有相应权限的人决定。

## 三、工作推进时怎样更新

### 开始与恢复任务

Agent 根据任务目标，从项目模型、规范、决定和历史记录中选择相关背景，并保留本次使用的资料及版本。后续可以据此判断：工作建立在什么前提上，这些前提是否已经改变。

恢复任务或准备交付时，重新核对有关变化。调查深度、工具和实现方法由 Agent 根据任务选择；遇到方案变化、新能力或相关问题时，继续查找已有能力与经验，并检查是否适用。

### 记录过程与变化

会话记录保留目的、涉及的任务和主题、重要活动与变化、决定和验证依据、未完成事项及下一步。记录同时说明可见参与者、资料范围和缺失部分。

重要纠正和决定在发生时记录，不必等到会话结束才总结。中断时保留最后能够确认的状态；缺失的过程明确标出，不补造历史。复盘可以连接当时认识与后来结果，但应让读者分清两者。

目标、规则或接口变化后，先保留原依据，再识别受影响的任务与项目知识，按已有授权更新。无法判断冲突要求中哪一项有效时，列明分歧和依据，交给有权决定的人处理。

### 多个会话共同推进一个任务

同一任务由多个会话协作时，任务记录维护一份共同的工作安排。按实际需要列出各项工作、承担者与关联会话、预期结果、依赖、当前状态、使用的资料版本和产物位置。每项工作应能被稳定引用，以便接续和更新；无需为了分工立即创建一套独立子任务体系。

需要分别表达执行活动与完成程度：

| 信息 | 回答的问题 | 判断依据 |
| --- | --- | --- |
| 执行活动 | 谁正在做什么，最近何时确认过？ | 会话或执行工具的活动记录，并注明观察时间与来源 |
| 工作状态 | 尚未开始、实施中、等待依赖、待核验，还是已经完成？ | 当前安排、阶段产物、具体阻塞与解除条件；取消或暂停另记原因 |
| 完成依据 | 哪些条件已满足，哪些未满足或未验证？ | 对应版本的产物、检查结果和所需确认 |

没有接入当前运行信息时，只能报告“最近记录为执行中，当前活动未确认”。长时间未更新不能证明工作已停止，关闭会话也不能证明工作已完成。已经提交产物但尚未核验的工作标为待核验，不能仅凭执行者的完成声明关闭。

会话开始前读取共同安排，确认自己承担的范围、预期改动和依赖。出现重叠时，先明确是共同编辑、独立检查还是接手，并说明各自边界。同一接口或同一份产物需要共同修改时，约定修改顺序或整合方式，不能仅靠文件名不同就认定互不影响。

共享要求变化后，分别记录变更已经保存、受影响会话已经读取、相应工作已经调整。后两项需要对应会话或结果的依据，不能从第一项推断。继续执行、整合或交付前检查是否仍有未处理的相关变化。

等待状态说明具体依赖、所需产物或版本，以及什么条件成立后能够继续。局部等待不必阻止其他可独立完成的工作；manager 同时展示仍在推进和受到阻塞的部分，不把整个任务简单归为等待。

会话中断或需要换人时，保留最后确认的结果、产物位置、未完成事项和现行依据。接手安排按授权确认后更新承担者，并保留交接来源。旧会话恢复时，先核对当前分工和资料版本；过期的进度汇报可以留作历史，不能直接覆盖接手后的状态。

各会话更新所负责工作的进展，不以局部完成直接改写整个任务的完成结论。任务安排中明确谁负责结果整合与最终核验，可以由获授权的同一 Agent 承担。manager 检查重复承担、遗漏、等待与未同步的变化，并提出协调建议；调配他人工作仍遵循既有授权。

任务完成需要各项必要工作已经整合，整体完成条件在当前版本得到核验，并取得任务约定要求的接受。要求或实现再次变化时，保留原完成记录，将受影响部分标为待复核，再判断需要补查还是返工；原有完成结论不能直接沿用到新版本。

上述分工与接续规则属于第一版范围，可先通过明确调用和顺序交接验证。真正并行时，两个会话可能同时读到旧分工，因此共享工具还需支持认领确认和更新时的版本检查，冲突进入重新协调。文档记录本身不提供互斥或实时同步；在对应实现验证前，不宣称能安全处理同时认领、同时改写和自动接管。

### 核验结果与汇总进展

讨论、决定、实施、验证和接受分别记录。会话结束不能代表任务完成，各项任务分别完成也不能直接证明项目目标达成。完成判断需要对照明确条件和有效依据；没有可解释的计算基础时，不生成进度百分比。

结果应说明哪些条件满足、哪些不满足、哪些尚未验证，并注明对应产物、来源、项目版本、运行环境、核验者和核验方法。Agent 自查、独立核验、人的接受和实际使用效果分别记录。

manager 在此基础上汇总变化、完成情况、依赖与冲突、资源限制、需要谁判断以及下一步。报告说明覆盖范围、使用的资料与版本；记录不全时，只对已覆盖的工作作出判断。

## 四、怎样更新长期知识

任务结果先服务于当前工作。准备放入 Base 的内容，还需要判断是否有跨任务价值、是否带来新信息，以及来源、主题、适用范围和状态是否明确。需要人确认的内容获得确认后再更新，冲突和不确定性保留可见。

观察与推断、提案与确认、有效与被替代、已验证与待验证分别表达。保存进长期知识库不会改变内容本身的确定程度。写入前清理敏感信息；完整私人对话、一次性回答和全部调试日志不复制进 Base。

更新时，比较同一主题和范围下的内容、来源、决定权限及替代关系。保留旧值与变化历史，避免重复导入同一来源时产生重复内容或动作。来源发生变化后，要重新判断相关认识是否仍然适用，不能只靠文件日期判断过期。

多人或多个执行过程同时更新时，还需比较各自使用的资料版本。互不影响的变动可以合并；重叠内容重新核对，旧版本上的修改不能直接覆盖新决定。这些要求保留在设计中，真实并发处理留待后续实现和验证。

## 五、Agent、工具与人的分工

Agent 负责理解内容、判断相关性、选择执行方法和归纳结果。工具按实际需要承担身份与引用解析、权限过滤、持久化、去重、版本比较、确定性检查和事件接入。

Agent 可以在授权范围内调查、记录和安排自己的工作。涉及他人任务分配、共同优先级、外部消息、资源承诺或风险接受时，遵循具体授权；已有授权持续有效。对人的责任判断还需要完整事实和适用权限，不能由摘要或失败次数自动决定。

共享资料时检查可见范围，读取权限不自动等于共享权限。跨用户检索和输出需要实际的权限控制，不能只靠提示词约束。面向人的资料围绕当前问题组织，让读者能够看清状态、影响、未知和下一步，并回到关键结论的来源。

第一版通过明确调用验证上述工作过程。自动获取会话、接收变更事件和通知参与者，需要在对应工具中接入后另行验证。首轮与后续验证的安排见[验证说明](VALIDATION.md)。
