# MVP 验证

状态：以下场景均为验收设计，尚未执行产品测试。文档检查与模型自评不能替代真实运行、多人使用或收益证据。

## 运行前固定

原请求、项目 revision、来源与权限、初始模型/决定、参与者及授权、两项任务的条件与依赖、session 输入顺序、模型/宿主、核验方式和预算。候选结果出现后不静默修改标准。

合成材料用于校准判断，真实材料用于实际验证；后续任务不预填预期答案。观察者核查原始证据，不用另一份摘要当真值。

## 必须覆盖的场景

| 场景 | 合格结果 |
| --- | --- |
| 无旧记忆接入 | 有来源的结构、关键流程、实际覆盖与未知；目录摘要不算完整模型 |
| 资料与实现不同 | 拟议设计和实现事实分别保留，正确指出影响 |
| 任务/会话交叉 | 一个任务跨 session、一个 session 涉及多任务时，接续与状态仍正确 |
| 混合活动 | 讨论、决定、实施和接受的来源与状态不混淆 |
| 标签反例 | 同标签不同 scope 不误联，跨标签真实依赖不漏联，改名后引用可追溯 |
| 新决定影响旧任务 | 关键行动前发现变化，复核适用性并按授权调整 |
| 局部完成 | 局部测试通过但整体条件缺证据时，仍显示未完成或未验证 |
| 并发与重放 | 重复来源不重复产生动作，旧写入不覆盖新决定，冲突可追溯 |
| 身份与权限 | 不泄露受限来源，不凭 Agent 归属获得项目决定或分派权 |
| 中断与缺记录 | 保留可证阶段结果、缺口与恢复动作，不补造结论 |
| 复盘与复用 | 当时条件和后来解释分开，后续任务核实经验是否适用 |
| 优先级与容量 | 暴露竞争依赖和约束，建议有依据，不虚构排期或承诺 |
| 普通任务与人的使用 | 小任务保持轻量，读者能定位状态、影响、未知与下一判断 |

语义通过对照输入、产物和人工判断核验；有实现后，引用、去重、权限、并发和持久化使用针对真实风险的机器测试。保留单任务原意、规范、可靠接续与知识准入等既有能力，不能为了协作退化。

## 分阶段判断

1. 合成语义演练：检查上表中的正确与错误情形。
2. 一次真实跨会话运行：实际产物、接续与核验有来源。
3. 后续复用：新任务及来源变化后仍正确使用知识。
4. 实际多人：身份、权限和并发分别有真实运行证据。
5. 人的收益：维护者独立完成一个具体判断，对照记录人工负担与运行成本。

任何一层通过不自动升级其他层。没有实际多人参与时明确报告这一缺口。当前所有层都尚未验证。

## 比较是否值得使用

基线为实际 agent-context-sync 加现有项目规则和协作工具。双方使用相同任务、来源、权限和可比资源，说明模型差异、顺序与答案泄漏限制。

记录目标偏差、遗漏的依赖/决定、错误完成声明、冲突返工，以及人工补背景、纠偏、协调、阅读、记录维护和额外模型成本。完成时间按统一开始/结束口径记录，不以 Agent 数或摘要数衡量收益；阈值与具体场景绑定，不虚构节省比例。

小任务负担应可接受，真实读者应能判断下一动作。观察结果直接记录在任务证据与简短项目日志中，暂不为未运行场景创建报告目录。
