# 项目协作 MVP 与验证计划

状态：2026-09-22 设计提案，产品运行未验证。当前目标见[能力目标](capability-goals.md)，对象与权限见[协作契约](../contracts/project-collaboration-contract.md)。

## 1. 首先证明什么

在一个真实项目中，让两项有依赖的工作跨至少三段 session 推进，后来的参与者能够正确恢复任务、发现相关新决定、核验局部与整体结果，并看懂当前阻塞和下一动作。对一人跨会话和实际多人分别保留证据。

原先的单任务治理与知识能力作为底层回归条件。只生成会议记录、模拟五个角色或安装插件，不能证明协作能力。

## 2. 首个切片

建议以[完整例子](../guides/cognition-flow.md)的“提交可靠性改进”结构构造首轮材料，再选择获授权的真实项目；示例本身为合成，未授权修改原巡检服务。

| 阶段 | 最小能力与产物 | 验证问题 |
| --- | --- | --- |
| 建立起点 | 来源清单、项目模型和现有决定 | 无旧记忆能否理解关键结构和未知？ |
| 整合输入 | 一份需求与实现有差异的附加资料 | 能否定位差异而不直接覆盖实现事实？ |
| 开始工作 | 一个工作线目标、两项相依任务、明确责任与条件 | 能否说明先后关系、适用规范和交付条件？ |
| 变化与接续 | 新决定、中断记录、一个基于旧前提的任务 | 能否在关键行动前找到影响并修正理解？ |
| 交付与综合 | 条件核验、会话记录、工作线报告及最小 Delta | 是否区分已讨论、已决定、已实现、已验证和已接受？ |
| 再次使用 | 一个新的相关任务与一个维护者问题 | 知识是否改善选择，人是否能够判断下一步？ |

开始真实运行前固定项目 revision、可见材料、参与者/授权、任务条件、模型/宿主、评价方式及费用或时间预算。模型扮演两个人的语义演练不能算实际跨用户验证。

## 3. 范围与成本控制

首轮只覆盖一个项目，不要求完整组织树、日历、企业排期、财务、人事绩效或跨项目组合管理。保留优先级理由、依赖、阻塞和容量约束的最小表达；没有历史数据不虚构工期、资源利用率或完成百分比。

单人小任务无需工作线或会议表单。五个 POV 可由同一 Agent 顺序承担，增加独立核验或并行执行时记录收益与成本。现有项目工具可继续拥有任务状态，通过引用连接，避免重复维护。

本轮实现范围为文档与验证设计；运行适配、自动捕获、共享数据库、UI 和调度器未实现。

## 4. 需要有与不需要先有

需要有：可追溯项目/任务身份、来源定位、轻量记录、明确的状态和授权、scope/read basis、知识准入、任务与工作线核验。

可先人工或显式调用：导入记录、识别活动、提出 tag、生成综合、复核冲突。必须诚实记录手工步骤，不能把显式调用称为自动触发。

不需要预先有：通用源码解析器、向量数据库、图数据库、五个服务、五个常驻模型或自动项目经理。确定性引用检查、去重和并发保护按具体实现缺口补齐。

## 5. 验收层次

1. **语义正确**：在明确的合成材料上识别关系、状态、授权和证据，包含负例；见[协作验收](../validation/collaboration-cases.md)。
2. **一次真实可行**：固定来源和条件，实际跨 session 完成工作，报告人工补充、失败和范围。
3. **后续有效**：新任务使用已接纳知识，源码/决定变化后能识别影响。
4. **多人运行**：真实身份、可见性、并发与冲突处理分别有证据。
5. **人的收益**：维护者能够独立判断状态、影响和下一动作；对照基线观察纠偏、协调、记录与运行成本。

任何一层通过不自动升级其他层。机器检查文档与链接只支持文档质量，不计作上述产品验收。

## 6. 实施顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| R1 当前 | 协作目标重塑、对象与职责、用例和比较设计 | 一套自洽、来源可查、状态明确的可评审设计 |
| R2 | 固定真实切片与最小记录/适配方式，开展一次运行 | 关键条件有实际证据，暴露失败与手工负担 |
| R3 | 针对失败实现最小机制，再做回归与新任务复用 | 有失败到修复的因果证据，保留单任务基线 |
| R4 | 实际多人、权限和并发验证，观察人的使用 | 运行与人工收益各有独立证据 |
| R5 | 确定分发形态与可持续替代范围 | 接入维护成本可接受，效果和限制可公开说明 |

本次用户允许重塑全部思路；阶段划分是 Agent 的交付安排，不限制后续明确实施指令。

## 7. 当前未知

真实协作载体与参与者、共享来源权限、首轮预算、事件可观测性、记录持久化方式和分发形态仍待运行准备确定。已有 agent-context-sync 及其他候选的新增协作覆盖需要重新评估，旧研究没有证明不存在可复用方案。
