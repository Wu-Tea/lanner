# Project Cognition：Agent 时代的项目协作

## 一、背景

Agent 提高了开发任务的执行效率，也让开发者能够同时推进更多工作。随着任务和会话增多，目标对齐、信息同步、依赖协调和结果核验的管理成本随之提高。完成开发工作所需的精力，开始更多地花在组织工作和判断结果上。

这一变化也让管理能力逐步下沉到一线开发者。开发者既要理解和实现需求，也要组织 Agent 的工作，维护不同任务之间的联系，并判断各项结果能否共同满足项目目标。即使只有一个人参与项目，也需要承担这部分管理职责。

Project Cognition 围绕这一变化提供支持：帮助人和 Agent 建立共同的项目认识，持续记录工作中的变化，并从项目整体判断进展与问题，让一线开发者能够以较低的管理成本组织更多工作。

## 二、基本思路

项目协作需要把相对稳定的项目认识与持续变化的工作情况联系起来。功能、结构、业务规则和已有能力，为新任务提供共同背景；讨论、决定、实际改动和验证结果，说明项目正在发生什么变化。前者帮助工作开始，后者帮助工作接续，并逐步修正对项目的认识。

我们把持续维护的项目认识称为项目模型，把任务推进和会话中的重要变化保存为工作记录。会话可以借鉴会议记录的方式，留下对齐、讨论、决策、执行和复盘中影响后续工作的内容。一项任务可以跨越多次会话，一次会话也可以涉及多个任务。

项目协调者（manager）综合相关任务与会话记录，从某项业务或工作的整体目标检查进展、依赖和冲突。它是可由 Agent 承担的一项职责，具体分工不要求固定数量的 Agent。标签帮助查找记录，实际内容、来源和依赖关系决定它们是否相关。

项目模型为任务提供背景，工作记录保留变化，协调工作将分散的结果联系起来；核对后值得长期保留的认识，再用于后续任务。三者共同支持持续协作。

## 三、需要具备的能力

| 能力 | 使用什么信息 | 形成什么结果 |
| --- | --- | --- |
| 调查并理解项目 | 用户指定的整个项目的代码、配置及可访问资料，不要求已有任务或旧会话 | 有来源的功能、结构、流程和可复用能力说明，同时标出调查范围与未知 |
| 整合补充资料 | 需求、设计、规范、外部资料及已有项目模型 | 资料与项目的关联，新增认识、差异和受影响的工作 |
| 支持任务开始与接续 | 原始请求、相关背景、规范、决定和历史记录 | 当前目标、范围、完成条件、有关变化与可复用经验 |
| 记录任务与会话结果 | 可见讨论、决定、实际改动和检查记录 | 可追溯的工作变化、结果、未完成事项与接续动作 |
| 汇总与协调相关工作 | 相关任务、会话及其依赖 | 整体进展、冲突、等待、需要人判断的问题与后续建议 |
| 更新长期项目知识 | 经核对且有后续使用价值的事实、决定和经验 | 带有来源、适用范围和变化历史的项目知识 |

从零开始的项目先记录目标和设计，随后补充实现事实。资料中的要求、讨论中的提案、实际实现和验证结果始终分开表达，不能把准备实现记成已经完成。

Agent 自主选择调查与执行方法，并在工作中继续发现和复用已有能力。涉及他人任务分配、共同优先级或交付承诺时，按明确授权处理。

## 四、第一版的范围

第一版先验证单个开发者使用 Agent 推进多项相关工作时，能否减少跨任务、跨会话的管理负担。需要覆盖项目调查、资料整合、任务接续、变化记录、整体进展整理和知识复用。

同一个任务也可以由多个会话分工推进。第一版需要记录谁承担哪部分、当前进展、依赖与交接，并区分会话活动、工作完成程度和整个任务的完成结论。先用明确调用和顺序交接验证这些规则；实时运行检测、同时认领与并发更新的可靠性，需要对应工具实现后另行验证。

初期允许用户手动提供资料和发起整理。自动获取不同工具中的会话、主动通知其他参与者，以及真实多人协作中的权限与并发处理，留待后续接入验证。无法访问的记录和未完成的检查应明确保留，不能补写成已知事实。

目前项目处于设计阶段，尚未实现为可安装使用的产品。具体界面、存储和接入方式根据验证需要确定；角色与信息规则见[设计说明](DESIGN.md)。

## 五、如何判断是否有效

验证重点是管理工作是否更容易完成。需要检查项目理解是否有依据，新任务是否获得相关背景，重要变化是否传递到受影响的工作，以及整体进展是否与实际结果一致。

同时记录开发者补充背景、查找信息、纠正偏差、协调任务和核对结果所花的精力，并计入新增的记录维护与模型运行成本。只有后续工作实际利用了这些信息，且总负担可以接受，才说明这套能力具有使用价值。

第一轮使用真实项目完成跨会话工作，并观察后续任务能否复用已有记录。单人验证不能证明多人协作有效，文档检查也不能代替产品运行。具体场景与比较方式见[验证说明](VALIDATION.md)。

现有 agent-context-sync 是接续工作和保存决定的比较基线。Project Cognition 需要在保留这些能力的基础上，进一步支持项目理解与协作，并便于其他开发者接入。目前尚未选定试用项目或完成产品验证。
