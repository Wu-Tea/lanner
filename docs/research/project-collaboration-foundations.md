# 从项目管理重新理解人和 Agent 的协作

日期：2026-09-22。本文是设计研究，不是产品效果证据。用户授权基于项目管理重塑项目；下文的产品取舍由 Agent 提出，尚未经过真实协作验证。

## 1. 本轮问题与来源

用户从会议类型想到 session 记录、参与者身份和跨会话 manager，进而指出项目目标需要从 taskworker 扩展到整个项目的协作。视频未提供链接或原文，因此只把用户描述作为构思来源，不声称复现视频观点。

本轮重新阅读此前引用的两篇美团文章，并查阅以下一手资料。仅提炼与本项目有关的原则；不宣称实现完整 Scrum、Kanban 或某种项目管理标准。

| 来源 | 原资料支持的要点 | 对本项目的设计启发（inferred） |

## 2. 对“每个人都参与 manager 工作”的解释

有用的部分是管理活动可以分布到工作发生的位置：执行者理解目标、形成计划、暴露依赖、自查结果、保留决定。系统帮助汇总与连接，减少人重述背景和追问状态的负担。

据此不能推出每个 Agent 都拥有分派他人工作、调整共享优先级或接受业务风险的权力。产品需要同时表达“谁做”“谁决定”“谁核验”“谁受影响”。一个人可以兼任这些职责，实际授权仍按具体工作和范围记录。

## 3. 哪些旧判断需要改变

| 旧设计侧重 | 本轮调整 | 保留的价值 |
| --- | --- | --- |
| 单次任务方向、结果与知识增量 | 同时表达项目目标、工作线和跨任务依赖 | 原请求、完成条件、证据与执行自主 |
| handoff 恢复当前会话 | 任务与 session 多对多，按工作关联恢复 | 小任务的简短接续 |
| 知识复用主要连接过去和当前任务 | 也连接同时进行的工作及新决定对旧任务的影响 | 来源、范围、时效与最小相关上下文 |
| manager 可能被理解为摘要生成者 | 负责综合状态、发现协调问题、提出调整并在授权内推进 | 汇总不自动成为决定 |
| 人类资料主要解释实现 | 同时帮助判断进展、变更、依赖和决定 | 同源知识、易读入口、真实读者验收 |

## 4. 取舍与范围

本轮建议先支持一个项目内的一人多会话与小团队协作。已有项目可独立建模；单任务可以轻量运行。跨项目资源组合、人事绩效、自动外部通知、日历、复杂排期和财务核算不纳入首个验证切片。

会议类型是交流目的；模块/功能是产品结构；工作线是持续变化目标；任务是可验收工作单元；session 是交流和执行的载体。这些维度不能合并成同一种标签。

建议先验证跨会话理解与协调是否减少遗漏，再选择宿主接入、共享记录和运行机制。五个 POV 是责任切面，不预先分配五个常驻 Agent；已有工具是否可覆盖新增协作职责仍需重新比较。
