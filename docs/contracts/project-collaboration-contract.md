# 项目协作契约

状态：2026-09-22 设计提案，运行未验证。用户已授权把产品方向扩展到项目协作；具体对象、角色、状态和机制属于本轮设计。本文拥有协作语义，其他文档通过引用使用。

## 1. 要解决的问题

一个项目中，不同的人和 Agent 会在不同时间理解问题、讨论方案、作出决定、实施和验证。系统应让他们在相容的目标与事实基础上工作，并知道哪些变化影响自己、谁需要处理、凭什么判断已完成。

当前验证范围为单项目内的一人或小团队。工作单元不依赖 GitHub issue、某个聊天产品或固定项目管理方法；已有载体可以作为来源。

## 2. 最小对象及关系

| 对象 | 含义 | 需要表达的最小信息 |
| --- | --- | --- |
| 项目 / 产品边界 | 被共同维护的系统、使用者与价值范围 | 项目身份、来源范围、受益者、关键约束与决策责任 |
| Goal | 希望带来的变化或价值 | 原始意图、范围、可判断的成功条件、优先级依据、决定责任 |
| Workstream（工作线） | 围绕一个持续目标组织的相关工作 | 关联目标、范围、负责人、任务关系、当前证据与未决项 |
| Task | 可以独立约定交付与核验的工作 | 原请求、目标、scope、owner、条件、依赖、状态与来源 |
| Session | 有起止或可接续边界的交流/执行载体 | 来源身份、参与者、任务/主题关联、记录覆盖、活动及结果引用 |
| Activity | session 内一段有明确目的的交流或执行 | 对齐/讨论/决策/执行/核验/复盘等目的、涉及对象与结果 |
| Participant / Agent Run | 人、Agent 身份及一次实际运行 | 归属、角色、可见范围、授权来源；实例/模型信息仅在追溯需要时保留 |
| Decision / Change | 具体取舍及其适用条件或变更 | 命题、scope、决定者、授权依据、受影响对象与 supersede 关系 |
| Risk / Issue / Action | 可能发生的问题、已发生的问题、待处理动作 | 条件或事实、影响、处理人/待分配、解除或完成条件 |
| Artifact / Evidence | 工作产物及支持命题的观察 | 稳定定位、revision/环境、支持范围、核验状态 |
| Knowledge / Topic | 可复用认知及项目主题身份 | 来源、scope、状态、关系、别名与长期准入状态 |

对象按需要出现；普通任务不必创建工作线、风险表或会议清单。没有来源的 owner、日期、优先级和承诺保持未定，不由模型补齐。

关系包括 `contributes-to`、`depends-on`、`affects`、`implements`、`decided-in`、`verified-by`、`supersedes`。关系的定义与成立证据必须可说明，不要求实现通用图数据库。

Task 与 Session 是多对多关系。一个 Task 可跨多个 Session，一个 Session 可涉及多个 Task。Workstream 可以跨模块；同一模块可以同时被多条工作线修改。Goal 的完成不能由 session 数、任务数或文件数自动计算。

## 3. 五个 POV 与人类责任

| POV | 可做的工作 | 输出与边界 |
| --- | --- | --- |
| 项目认知者 | 调查项目、整合材料、识别主题及关系、提出模型修正 | 有来源的模型/Delta，不把资料作者或模型推断当人类决定 |
| 任务执行者 | 理解任务、复用能力、计划、执行、自查、报告影响 | 实际产物和状态变化，只在任务授权内行动 |
| 会话记录者 | 提取活动、纠正、决定来源、证据和未完成项，提出关联 | 忠于可见记录，标明缺口，不录入完整私人对话 |
| 工作线管理者 | 跨会话综合、追踪依赖与未决项、分析变更和容量、提出协调动作 | 有 read basis 的工作线状态与建议，不能凭角色名获得调度权 |
| 结果核验者 | 将任务/工作线完成条件与来源比对，检查知识候选 | 明确范围、方法、判定和盲区；自查与独立核验有区别 |

POV 不等于进程、独立模型或人格。同一 Agent 可切换，多个参与者也可承担同类责任。增加并行角色前应说明独立性或容量上的实际收益。

人类职责按具体范围记录：目标与优先级负责人、执行 owner、必要的领域决策者、验收者和受影响参与者。单人项目可以由同一人兼任；团队项目不能把“该 Agent 的用户”默认当作整个项目的最高决定者。归属关系不自动授予读取用户全部会话或代表其作出承诺的权力。

## 4. 管理动作的授权层次

1. 读取已授权来源、归纳、发现冲突和提出方案可以自主进行。
2. 在已授权任务内更新记录、拆解自己的工作和安排调查可以自主进行；不自动扩大目标。
3. 分派其他参与者、调整共同优先级、改动里程碑/预算或调用有副作用的工具，需要已有明确授权覆盖对应动作、scope 和资源；授权可持续沿用。
4. 业务接受、风险接受和相互冲突的合理意图，由有责任的人决定。证据无法代替价值取舍。

manager 应给出具体受影响项、推荐动作、依据和需要谁决定。执行授权不明时只提出建议，仍可推进不依赖该决定的工作；授权齐备时直接执行并留证，不逐步重复索取确认。本轮文档重塑不表示已经启用任何运行调度或外部消息。

## 5. 以目的记录活动

| 活动目的 | 结束时应留下什么 | 不应自动推导什么 |
| --- | --- | --- |
| 对齐 | 已一致目标、范围、术语和未解决分歧 | 没有反对不等于确认 |
| 讨论 | 问题、候选、论据、未知与下一调查 | 讨论充分不等于已选方案 |
| 决策 | 被选择的具体命题、决定人、scope、理由和影响 | 人接受设计不等于实现完成 |
| 执行 | 改动、运行观察、偏差、实际交付与未完成项 | 有提交不等于达到业务价值 |
| 核验 | 条件、证据、方法、满足/不满足/尚未验证 | 自评不等于独立评审或人的接受 |
| 复盘 | 当时目标与条件、实际结果、解释、改进动作及待验证项 | 事后解释不自动成为当时原因 |
| 责任核查 | 职责依据、已知条件、事件事实、缺口与人类裁定入口 | 不按摘要、失败次数或 Agent 用量自动归责 |

类型允许混合或变化，参与者无需先选择会议表单。一个无代码改动的讨论 session 可以成功结束，一个有代码提交的任务也可能尚未通过核验。

## 6. 会话记录与项目相关性

记录的最小集合是：目的与范围、可见参与者及授权依据、关联任务/主题、重要变化、证据/决定引用、未完成项与接续动作。原始记录保留在其授权来源；缺失区间和不可访问部分应明确。中断时保留最后可证的阶段结果，恢复后再补差异。

Session 自行提出模块/功能标签及候选关联。主题来自项目模型的稳定身份，tag 作为别名或索引；新名称可以暂存，后续核对合并并保留旧引用。重要条目需要连接 Task、Decision、Artifact 或实际模块关系，不能只剩自由标签。

manager 检索顺序由 Agent 选择，但判断至少考虑直接任务引用、相同主题及 scope、依赖影响、决定的生效/替代关系和来源时点。保留为什么纳入、为什么排除重要相近候选。跨模块但有依赖的工作仍相关；同标签的不同环境或工作目标可以无关。未命中不能证明不存在。

## 7. 状态与变更

任务可用 `proposed / active / blocked / in-review / completed / cancelled` 表达推进状态，精确枚举待验证。结束 session、完成任务、满足目标、接受结果、知识准入是独立状态。

推进证据应回答具体条件满足了几项、哪些关键条件缺失。只有在有稳定分母和权重依据时才给完成百分比。阻塞记录依赖对象、解除条件与处理责任；风险尚未发生，issue 已有观察，不混为同一种状态。

目标、范围、优先级、决定或依赖发生重要变化时：保留旧基线 → 说明变化与来源 → 找出受影响任务、知识和产物 → 取得必要决定或引用已有授权 → 更新当前状态并保留历史。开放任务恢复或提交结果前核对与自己相关的新变化；不凭旧摘要继续接受已失效前提。

## 8. manager 的综合循环

输入是工作线问题、范围、可见记录、项目模型、当前决定与证据。输出依次回答：

1. 目标及本轮观察范围；
2. 相比上次，哪些可证事实或决定变化；
3. 已完成、未完成、阻塞和依赖；
4. 争议、风险、容量约束和需要谁判断；
5. 推荐下一动作及授权状态；
6. 可复用的 Knowledge Delta。

综合保留 read basis、覆盖时点、来源集和主要盲区。重复导入同一来源不重复产生动作或决定；并发提交基于旧 read basis 时先比较受影响主题与 scope，非重叠变化可合并，重叠变化标明冲突并重新核对，禁止最后写入者静默获胜。这是语义要求，不表示已实现事务系统。

综合可以按用户请求、任务交付、重要决定或明确检查点触发；事件适配未验证时仅承诺显式调用。默认不发送例行噪声；若后续启用通知，应仅面向获授权接收者报告可行动变化。当前不创建通知或自动化。

## 9. 知识和工作状态的归属

工作记录拥有当前任务状态、原始会话来源和行动项。Base 拥有跨任务的项目知识及语义关系，引用工作记录与证据；manager 报告是上述来源在某时点的综合投影。三者可以位于同一存储中，但不能各自维护一份互相竞争的事实。

项目模型更新要经过[知识准入](base-knowledge-contract.md)；工作状态更新遵循其来源和授权。报告难读可以改表达，发现新语义需回到对应 owner 修正。归档 session 不删除仍被任务、决定或知识引用的证据。

## 10. 验证与边界

参见[协作验收](../validation/collaboration-cases.md)：跨会话接续、并行冲突、依赖变化、混合会议、资料整合、权限和成本分别验证。多用户输入可以先用显式标为合成的材料验证语义，但不据此宣称多人运行已实现。敏感性过滤必须作用于检索、综合和输出，模型可读取的私人信息不自动属于共享项目资料。
