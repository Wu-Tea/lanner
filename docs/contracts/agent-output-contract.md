# 工作与结果契约

状态：2026-09-22 语义设计；继承原任务证据要求，扩展协作上下文。字段与运行机制未冻结。

## 1. 任务理解

Task Frame 保留原请求、目标、scope、完成条件、相关规范、知识与决定引用、重要假设和人类决定点。协作任务按需要补充工作线/目标关联、执行 owner、依赖、读入基线与受影响参与者；缺失信息保持未定。

从项目来源可查的事实由 Agent 调查；缺失的意图与关键授权由人决定。用户目标、范围或条件的重要变化必须可见。具体步骤、工具、验证方法由 Agent 自主选择。

首次建模可以直接成为任务，Base 可以为空；整体调查范围和实际覆盖分别记录。普通局部任务无需全项目重扫或填写固定表单。

## 2. 执行与阶段记录

计划或前提变化、进入新模块、新增能力、遇到失败和用户纠正时，重新取回适用规范、已有能力、经验及相关工作的新决定。检索没有结果不证明项目不存在。

记录关键变化、证据、未完成项与接续动作，保留当时依据。执行者提出会话关联和知识候选；记录不要求保存完整工具输出或内部推理。任务恢复与结果提交前，检查自己依赖的目标、决定或接口是否发生影响本次判断的变化。

## 3. 结果需要回答什么

1. 本次直接结果与对应目标；
2. 哪些条件满足、不满足或尚未验证，依据哪些实际产物；
3. 适用规范、影响、风险与未知；
4. 当前任务状态和未完成事项；
5. 相关依赖是否解除、新决定或变更影响哪些工作；
6. 需要人判断的具体命题、scope 和推荐动作；
7. 可选 Knowledge Delta。

表达采用普通语言即可。任务状态是可核验的声明，不等于人工接受；Session 结束状态由[协作契约](project-collaboration-contract.md)单独维护。

## 4. 证据强度

| 结论 | 所需依据 |
| --- | --- |
| 实现事实 | 固定源码、配置、diff 或实际产物 |
| 测试/运行行为 | 命令、环境、revision、观察及范围 |
| 跨模块解释 | 主要来源、关系路径、scope 和推断状态 |
| 全局不存在/完整覆盖 | 实际调查范围、方法、排除项和盲区 |
| 决定、承诺或业务接受 | 有权限的人对具体命题和范围的确认 |
| 工作线进展 | 相关任务条件、实际交付、决定和依赖，不只汇总执行者自述 |

历史运行不是本次复验；计划不是执行；文档写入不是产品实现；外部案例效果不是本项目效果。核验者需要打开相应来源，访问不到或 scope 不符的部分保持未验证。

## 5. Outcome Review

核对目标、条件、规范、证据、影响和未知。重要条件记录核验者、方式、来源和判定理由。可以由同一模型自查，独立模型/人类核验另行标明；没有校准不能声称自查等价于独立接受。

- `pass`：必要条件均有充分证据，相关规范满足；不等于人的接受或知识准入。
- `revise`：存在可以修正的目标、产物、表达或证据缺口。
- `needs-human-decision`：需要明确价值取舍或授权判断。
- `blocked`：必要来源或外部条件不可获得，写明具体缺口。

必要条件未验证不能仅因产物完整而通过。业务收益的成功条件单独核验，局部任务完成不能自动推进 Goal 为完成。

## 6. 不同活动的结果边界

讨论可以以清楚的候选和未知结束；决策需要决定来源；执行需要实际产物；复盘需要当时条件与后续行动；核验需要条件判定。一个 session 中的不同活动可分别记录，禁止用“会议完成”代替 task 验收。

manager 的报告必须给出工作线范围、read basis、纳入来源、变化、当前状态、依赖/冲突、需要谁判断和下一动作。对于覆盖不全的工作线，只能给出局部综合。

## 7. Knowledge Delta

候选说明稳定主题、scope、来源、观察/推断、确认状态、新增/修正/冲突/失效/替代动作及跨任务价值。它可以来自阶段工作、资料整合、单次结果或跨任务复盘。

一次任务可以没有 Delta；候选不获准入不否定本次任务结果。受保护决定有精确确认来源，敏感信息在进入共享候选前清理。具体准入见[长期知识契约](base-knowledge-contract.md)。

## 8. 验证方式

确定性行为使用针对真实风险的机器验证；语义工作通过固定输入、预期性质、负例和人工判断核验。自评、合成回放、真实使用、独立复用与成本对照分别报告。验收入口为[协作案例](../validation/collaboration-cases.md)和[既有能力案例](../validation/golden-cases.md)。
