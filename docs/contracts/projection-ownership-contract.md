# 信息所有权与资料契约

状态：2026-09-22 协作设计。每类信息和 scope 有唯一权威 owner，其他文件提供引用、历史或面向读者的表达。

## 1. 各类产物拥有什么

| 产物 | 拥有内容 |
| --- | --- |
| 源码/配置/构建 | 指定 revision 的实现和机器声明 |
| 测试/运行证据 | 绑定命令、环境和条件的观察 |
| 决定记录 | 有权限的人确认的命题、理由、scope 和替代关系 |
| 工作记录 | Goal/Workstream/Task 的工作状态、依赖、行动项，以及 Session 活动引用 |
| 原始 session 来源 | 授权范围内可观察的交流和执行，不默认公开全文 |
| Base | 跨任务知识、稳定主题、scope、状态、来源和长期关系 |
| Task Frame / Result | 本次理解、完成条件、结果与核验依据 |
| Knowledge Delta | 对长期知识的候选变化 |
| manager 报告 | 某个范围与时点的综合、解释和推荐动作；当前事实引用 owner |
| 人类资料 | 读者问题、解释顺序、选择范围与表现 |
| README / AGENTS | 项目入口 / Agent 工作规则 |
| handoff / session-log | 当前接续游标 / 历史里程碑 |

上述是逻辑职责，可以共享一个存储。当前仓库尚未实现通用工作记录存储或运行中的 Base；设计文档与决定分别维护本项目的现阶段语义。

## 2. 正常信息流

用户目标与来源 → Task/活动 → 实际工作与核验 → 更新工作记录 → manager 综合；其中有长期价值的部分形成 Delta → 准入 → Base → 后续任务和项目资料。

一次任务完成不要求知识准入；工作线综合不直接改变目标或验收。实现、进度、决定和知识的变化分别写回对应 owner，再重建报告。

## 3. 编辑资料

只改措辞、布局或导航可以直接调整表达。修正实现解释先核对源码，再更新相关知识；新增设计理由需要决定来源；改变任务状态需要条件与证据；改变共同优先级需要对应授权。

manager 不能通过重写总结取消一项任务或覆盖已确认决定。保存的 current 报告至少保留范围、read basis/时点和关键引用；候选模型或未核实变化标为 preview。

## 4. 漂移与历史

来源变化后标记受影响资料待重建，知识语义另行复核。handoff 不指向当前任务时更新游标，session-log 仍保留当时状态。被 supersede 的决定和知识保留历史链接，旧报告不能靠较新文件时间获得权威。

删除或重建表达不损失知识；归档工作记录时仍保留有效引用所需的证据。私人来源不因被报告引用而自动获得共享权限。

## 5. 仓库入口约束

README 保留用途与按问题的入口；AGENTS 保留行为、授权与证据规则；handoff 保留当前目标、状态、下一动作和阻塞；session-log 保存历史；decisions 保存长期理由；案例只说明自身证据与适用范围。output、旧 schemas 和未采纳 Skill 不是当前产品实现规范。
