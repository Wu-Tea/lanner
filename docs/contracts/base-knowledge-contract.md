# 长期知识契约

状态：2026-09-22 语义设计，物理 Base 尚未确定。

## 1. Base 的目的与归属

Base 保存跨任务有用的项目认识，供不同的人与 Agent 选择上下文、理解影响和继续工作。源码拥有实现，运行证据拥有观察，决定记录拥有人类理由，工作记录拥有任务/session 当前状态；Base 保留它们之间有长期价值的语义、状态与引用。

共享 Base 不意味着共享所有私人会话。来源可见范围、命题 scope 和确认权必须随知识保留。manager 报告和人类资料引用权威 owner，不自建平行的当前事实。

## 2. 首次建立与持续更新

首次独立调查可以从空 Base 开始，形成项目模型、来源覆盖、关系和未知；经核验与准入建立初始知识。调查明细留在任务证据，长期部分按复用价值选择。

从零项目先记录已确认意图与拟议设计，出现实现后再增加事实。附加材料先识别其角色、时点、scope 与冲突，再修正模型。资料作者的叙述不自动成为独立验证。

## 3. 值得保留什么

- 项目目标、规范、不变量和已确认取舍；
- 模块/功能/业务主题身份、职责、重要关系与流程；
- 可复用工具、能力入口、适用条件和可用性证据；
- 经验证或明确标为推断的经验、研发路径、风险和重要未知；
- 跨任务仍有价值的工作演变、依赖约束和决定引用。

临时进度、完整会议文本、一次性回答、完整日志和内部推理留在原 owner。Base 不因增加项目管理范围而变成所有工作记录的复制库。

## 4. Admission Test

候选须有跨任务价值、稳定主题、足够 scope、来源或推断依据、独立状态、实际增量、已暴露冲突、必要的人类确认，并完成敏感性清理。

直接可定位事实可按已授权政策登记；目标、规范、业务语义、架构取舍和风险接受必须有相应决定。准入只表示值得保留，不把 inferred 变为 observed，也不把未验证变为已验证。

## 5. 状态与适用范围

每条知识分别回答：直接观察还是推断；提案还是已经由人确认；当前有效还是被替代；证据是否适用于本次范围；只是候选还是已进入 Base。

Scope 按需要包含项目、分支/revision、环境、平台、时间和权限边界。不同 scope 的值可以共存，重叠且不兼容的命题需要冲突判断。来源能力见[知识语义](knowledge-contract.md)。

## 6. 过程获取与事后复盘

保留用户于 2026-09-10 提出的两种获取方式：迭代中的直接需求/记录，以及事后复盘得到的全貌。

过程捕获保留当时目标、已知条件、尝试、实际观察和纠正；复盘结合相关记录、当前实现、决定和验证，连接跨阶段关系并发现遗漏。manager 可以负责工作线综合，项目认知者负责模型语义，二者共用准入。

当时依据与后来解释分别记录，缺少历史不能补写成事实。复盘对系统条件和可验证改进负责，人的责任裁定需要明确依据与权限。完整报告留在工作记录，长期部分进入 Delta。

## 7. 主题、关系与检索

模块/功能有稳定身份，可拥有标签和别名。工作记录引用这些主题，同时保留 Task、Decision、Artifact 等具体关联。tag 相同不证明因果或同一工作线；跨模块依赖仍能使记录相关。

检索按任务目标、拟做能力、问题特征、模块关系和当前决定展开；提供相关原因、入口、scope、状态及来源。新任务、方案变化、跨模块修改和失败时复核适用性。未找到与不存在分别表达，低相关资料按需展开。

## 8. Delta、版本与冲突

候选动作包括新增、修正、矛盾、待复核和替代。记录 read basis，比较同主题、scope、来源、时间和 supersede 关系；重复引用不重复产生知识。

旧基线上的候选不能静默覆盖新知识。非重叠变化可合并，重叠变化复核并暴露冲突；涉及合理意图冲突时由相应负责人判断。保留旧值和替代链，工具变化信号与 Agent 语义判断分别记录。

已接纳变化产生逻辑 revision，物理实现可以是文件或已有服务。生成报告失败不回滚已接纳知识；来源变化使受影响知识待复核，不能只按文件年龄决定失效。

## 9. 人类资料与隐私

项目知识的 current 资料使用已接纳 Base；候选可以生成明确标记的 preview。当前进展资料引用工作状态 owner，两类来源各自可追溯。

跨人输出按共享权限选择，排除凭据、完整私人会话和无关个人信息；保留必要来源定位时也应避免泄露受限信息。资料可重建，新的语义修正回到对应 owner。

## 10. 健康与验证

知识价值通过后续工作实际使用证明；保存成功、查阅、采用与收益分别记录。检查来源失效、错用经验、并发覆盖、标签误联、长期重复和人的维护成本。规模未证明需要前，不预设向量索引或通用图数据库。
