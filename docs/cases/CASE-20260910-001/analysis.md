# CASE-20260910-001：成品之外，保留设计形成的依据

日期：2026-09-10。来源为用户提供的两张手机界面截图与产品演化解释。[图1](source-1.png)、[图2](source-2.png) 已原样保存。此案用于讨论知识需求，未复现具体手机的产品缺陷。

## 这个例子补充什么

用户指出：外观相似的产品，可能没有继承促成软件适配的探索过程。其解释是，追求特定圆角和屏幕形态，逐步带来了状态栏位置、Wi-Fi 与电量显示等配套设计。

初步判断（inferred）：项目知识应保留成功方案的形成依据，包括目标、约束、可观察尝试、结果和取舍，以及这些依据何时不再适用。后续 Agent 才能判断一个特殊设计解决了什么问题，避免将必要适配当作可以统一掉的非标准做法。这是现有研发路径能力的具体使用场景。

## 可以观察到什么，哪些仍是解释

| 内容 | 来源与状态 | 能支持的范围 |
| --- | --- | --- |

## 要留下怎样的研发经验

以下是分析所需的问题结构，属于 proposed；不是补写苹果或小米的真实开发记录：

| 需要回答的问题 | 对后续工作的用途 |
| --- | --- |
| 当初想实现什么体验，受哪些形状、空间或操作约束影响？ | 判断当前改动有没有破坏原目标，定位相关前提 |
| 尝试过哪些候选，实际出现了什么现象？ | 复用可用机制，避免无依据地重走已知失败路径 |
| 为什么选择现在的做法，证据与取舍是什么？ | 理解现有特殊设计的责任，判断新方案能否替代 |
| 哪些显示和交互需要配套调整？ | 从外观变化联想到状态信息、导航和内容区域的相关影响 |
| 哪些条件改变后，需要重新验证或允许换方案？ | 让旧经验随条件变化复核，避免把一次成功固化成永久规则 |

一种可能的研究问题链是：期望的外形与握持体验 → 可用显示空间/开孔位置 → 常规布局的适用性 → 候选适配与实际观察 → 当前方案及其条件。每一段关系都需要来源；未知处可以提出假设和调查问题，不能用合理叙事填成既定历史。

应保存影响后续判断的少量过程证据及理由，原始资料按需引用。成功试验、约束被发现和重要取舍同样可以触发记录；不要求发生报错或等到最终收尾，也不要求保存全部操作流水或模型内部推理。

## 对 Agent 的具体意义

拟检验的失败场景是：Agent 只看见最终布局或代码，按照通用模板重构，遗漏了原方案解决的局部问题。这是从案例推导的风险，尚不是本案已经观察到的 Agent 执行失败。

预期行为是：修改相关形态、模块或约束之前，取回对应设计依据与适用条件；用原目标和证据核对当前方案。允许更好的替代实现，核验的是约束和体验目标是否仍满足，而非要求外观或代码永远保持原样。

这与 [mouse 案例](../CASE-20260908-001/analysis.md) 互补：mouse 有“知识已找到、已读到，但应用与接续仍出问题”的实际记录；本案突出“如果只保留最终状态，后续判断会缺少哪些形成依据”。二者都要求相关知识参与当前选择。

## 落在现有能力中的位置

- **PC-G4 可靠知识维护：** 持续开发时留下有证据的探索、成功适配、重要取舍与相关约束。现有 [长期知识契约](../../contracts/base-knowledge-contract.md) 已包含 Development path、Decision 和 Risk and lesson；建议把这里的用途补进验收，不另建一套经验库。
- **PC-G2 开发中使用知识：** 在重构、统一样式或改变相关前提时，取回形成依据并复核适用性。只检索同名工具或报错经验不足以覆盖这个场景。
- **PC-G0 首次建模：** 源码与截图可以支持当前实现、结构和布局事实；研发原因需从决定、试验或反馈恢复。缺失时明确未知，模型解释保留 inferred，不能承诺仅靠全量扫描还原所有历史。
- **PC-G5 人的项目理解：** 资料要帮助维护者回答“这里为什么特殊、动它会影响什么、哪些条件变了可以重新考虑”。PC-G1 的当前目标和 PC-G3 的证据核验继续约束这些判断。

## 验收建议与范围

建议给已有 GC-008、GC-013、GC-017、GC-018 增加以下变体，均为 proposed，未执行试验：

1. 提供有真实来源的约束与探索记录，要求统一或重构界面；Agent 能识别相关依据，证明新旧方案如何满足当前目标，而不是只复刻外观或套通用模板。
2. 保留同一历史理由，但改变关键前提；Agent 能识别适用性变化并重新评估，不机械坚持旧方案。
3. 只提供成品与源码、不提供研发历史；Agent 能区分当前事实和推测，指出关键证据缺口，不编造尝试、失败或设计者动机。

评测需要单独准备可核对的约束、过程与结果，不能用本案对品牌研发过程的推测充当标准答案。当前没有实际使用或对照数据，也没有选择新的 Skill、Hook、存储或插件形态。
