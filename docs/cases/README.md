## 怎样记录

在 `docs/cases/<case-id>/analysis.md` 按用户要研究的问题展开，不要求用户填写表单。内容随问题复杂度选择：

- 原问题、材料来源及必要的 revision、环境与调查范围。
- 重要发现及证据，区分用户报告、实际观察、Agent 推断与未知；观察结果与原因推断分开。
- 与哪项能力或使用要求有关，证据支持到什么范围；比较目标变化时注明参照文档/基线及其时点。
- 需要补证、修订或决定什么；修订建议列明原条目、变化、理由、影响、确认状态与后续去向。

案例的业务目标、约束、工具和技术选择按其来源范围理解，不自动成为本产品的目标、规范、依赖或实施授权。隐私与知识来源遵循仓库 AGENTS 及相关契约。

## 案例怎样影响产品

核对事实、补证和案例分析可直接推进。涉及产品目标、scope、完成条件、规范或已确认取舍的变化，按相应用户确认更新正式文档与决定，再生成新基线；已有明确修改指令持续有效，不重复询问。依据见 [记录与范围决定](../../.agent-context/decisions/DEC-2026-09-07-005-pre-case-baseline-and-scope-separation.md)。

如实报告案例揭示的遗漏、错误假设或目标冲突，按原因和适用范围判断其意义。旧基线保留历史状态，新发现可以支持修订方向。
