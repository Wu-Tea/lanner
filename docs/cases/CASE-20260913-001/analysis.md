# 从零认识这个设备检查项目

假设学校有几台水泵，需要每天安排人检查是否漏水、声音是否正常，发现问题后还要留下照片并记录处理情况。按安排去查看设备并记录结果，这件事叫“巡检”。这是虚构例子，用来帮助理解原项目的工作。

这个程序负责记录有哪些设备、每台要检查什么、哪次由谁执行、检查后填写了什么结果。你可以从普通的增删改查看起：录入设备是一条记录，今天的任务是一条记录，回答“是否漏水”又是一条记录。理解这些记录为什么分开、怎样用编号关联，才能继续看路线计算和提交优化。

## 先从一遍完整的检查开始

第一篇 [学校怎样安排一次设备检查](business-map.md)，会按一次工作的顺序介绍设备、检查内容、路线、计划、任务和结果。每个名字都有具体例子和要保存的数据。先读这一篇，再进入下面两个功能。

[推荐检查顺序](route-recommendation.md) 从“今天检查设备 01、02、05”开始，先查相关资料，再用二维数组和循环比较不同顺序，最后算出路程。正文会解释资产、权重和矩阵，不要求先学过寻路算法。

[提交检查结果](submission-reassessment.md) 从“小林填完答案、拍了照片，点击提交”开始，解释为什么一次保存会很慢、照片怎样和答案分开处理、后台继续保存是什么意思。用户提供的优化方案在这里与当前代码对照。

读完后可以 [打开 Demo](../../../demos/recommend-lines/index.html)。这是用虚构设备做的小程序，帮助你实际改变输入、查看计算和结果。下载解压的使用方式见 [运行说明](../../../demos/recommend-lines/README.md)。
