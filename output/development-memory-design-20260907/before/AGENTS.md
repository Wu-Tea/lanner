# AGENTS.md

## Startup

- 进入本仓库后，先读 `.agent-context/handoff.md`。
- 再读 handoff 引用的决策和 `.agent-context/session-log.md` 最近相关记录。
- 按当前任务选择相关规范、Base 内容和来源；README 用于建立入口方向。
- handoff 与仓库事实出现差异时，先报告差异，再以正确来源重新定位当前任务。

## Attention Order

编写产品说明、规格、任务和资料时，按以下顺序安排读者注意力：

1. 当前要完成的事情；
2. 读者或 Agent 已有的上下文；
3. 与当前决定直接相关的规范；
4. 需要采取的主要动作；
5. 动作产生的可见结果；
6. 需要时再展开边界、历史和次要细节。

优先使用正向责任、输入、输出、完成条件和验收标准描述能力。边界说明放在对应职责之后，安全、证据和权威性边界保持明确。

## Product Mainline

Project Cognition 稳定维护四件事：

1. `direction`：当前任务目标、scope、完成条件和人类决策点；
2. `policy`：项目已确认并适用于当前任务的规范；
3. `outcome`：结果需要回答、证明和暴露的内容；
4. `knowledge promotion`：任务发现进入长期 Base 的条件。

Agent 自主选择仓库调查、工具、工作深度、推理、验证和表达方式。过程约束以真实项目失败为依据，并保持最小充分。

## Work Rules

- 直接接受用户的普通自然语言任务。
- 首次接入项目支持独立的全项目调查与初始建模，不依赖已有会话历史或先完成开发任务；Agent 自主调查，结果显式说明覆盖、来源、关系和未知。从零项目区分目标/设计与已实现事实。该能力不要求自建通用解析器。
- 保留原始请求，并用简短 Task Frame 表达目标、scope、完成条件、相关规范和人类决策点。
- 让用户能够看见会实质改变目标、scope 或完成条件的解释。
- 为 Agent 选择完成当前任务所需的项目事实、规范、决定、风险和未知项。
- 结果评审聚焦目标命中、规范遵守、证据、适用范围、影响和未知项。
- 重要完成条件对应实际产物或执行证据，标明核验方式及满足、不满足或尚未验证；普通任务可以简短表达。
- 结论风险决定证据强度：局部结论使用局部证据，全局结论同时说明调查范围和盲区。
- 普通局部任务采用轻量路径；结构性任务使用与其影响相称的设计和验证材料。
- 模型能够可靠完成的调查、归纳、画图和自我复核直接由模型承担。

## Knowledge Rules

- 用 derived fact、declared intent、observed evidence、inferred explanation 和 ephemeral context 表达不同知识种类。
- 用 observed、inferred、proposed、human-confirmed 和 superseded 表达来源与生命周期状态。
- 每项 Agent 推断明确标为 inferred；每项用户确认精确绑定命题和 scope。
- 代码和配置支持实现事实；业务原因和架构取舍由已确认 decision 支持；测试和运行证据绑定其 revision 与环境。
- 冲突判断同时比较 topic、scope、value、authority 和 supersede 关系。
- 过期判断使用依赖、影响和证据变化，并保留原始历史。
- Base 保存跨任务有价值的稳定事实、关系、风险、决定和重要未知项。
- Task Result 服务当前工作；Knowledge Delta 提出长期知识候选；Promotion 决定 Base 更新。
- 进入 Base 的内容保留来源、scope、状态和必要的不确定性。
- 人类通过明确动作维护目标、规范、架构取舍和风险接受。

## Human-facing Content

- 人类资料使用已确认 Base 内容生成，并共享同一语义身份和来源。
- 资料围绕读者的真实问题帮助其定位影响、未知和待决定事项；生成状态与真实使用反馈分别记录。
- 从可观察用途、输入输出和运行边界开始，再按阅读前置关系引入内部名词。
- 用具体项目行为、完整过程、例子和证据组织内容。
- 根据读者问题选择文章、框架图、流程、模块细节、关系或证据形式。
- 资料语义变化先形成 Knowledge Delta，经确认后进入 Base 并重新生成投影。
- 资料支持从总体进入细节、保持当前焦点、查看证据并返回原位置。
- 每个入口突出一个主要问题和一个主要下一动作；历史和次要信息按需展开。

## Implementation Rules

- 使用 Golden Case 和真实项目任务识别重复失败，再选择实现机制。
- 优先通过清晰的方向、规范和结果契约解决治理问题。
- 对确定性校验、持久化、集成和自动触发使用工具。
- 核心契约保持模型、供应商、语言和框架中立。
- Skill 聚焦可复用任务能力，并为强模型保留执行自由。
- Hook 触发已确认的检查点，人工决定继续由明确确认完成。
- 工具负责校验、记录、引用完整性和可重建投影；Agent 负责项目语义理解。

## Verification

- Golden Case 固定目标、可用上下文、项目 revision、相关规范、预期结果性质和验收边界。
- 评价不同模型时比较方向、规范遵守、证据、未知项和结果可用性。
- 确定性实现通过机器测试；体验结论标明合成评测或真实用户反馈。
- Agent 自评、离线 benchmark、生成成功和真实用户验收保持各自独立状态。
- 单次任务成功、后续知识复用、独立运行和成本收益分别保留证据范围；首轮实验记录要求见 Golden Cases。

## Safety and Privacy

- 写入长期资料前清理 secrets、cookies、tokens、私钥、完整私人对话和无关个人信息。
- 破坏性修改、历史重写、生产发布、数据迁移和覆盖用户数据遵循明确授权。

## Context Maintenance

- 重要设计、实现或评审后使用 Agent Context Sync 更新 `.agent-context/`。
- `handoff.md` 保存当前目标、状态、唯一下一动作、阻塞和问题。
- `session-log.md` 保存历史；decision record 保存长期理由。

## Reporting

- 对用户按“任务”和“功能”汇报。
- 完成工作后报告改了什么、为什么、验证结果、剩余限制和下一动作。
