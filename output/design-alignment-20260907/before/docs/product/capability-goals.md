# 产品能力目标与组件对应

Base 读取基点：`pc-base-20260907-01`，记录 PC-G1–PC-G5、PC-V1。  
来源入口：[已确认知识索引](../../knowledge/base.md)。这是已确认目标的导读；下表组件是本次实现选择，其效果仍待验证。

Project Cognition 帮助维护者把实际工作交给 Agent 后，仍能掌握任务方向、交付依据和关键取舍，并让后续的人与 Agent 继承可靠项目知识。

| 能力目标 | 用户应看到的结果 | 需要的组件职责 | 当前采用基础 | 验收方式 |
| --- | --- | --- | --- | --- |
| PC-G1 保持目标 | Agent 的解释可与原请求比较，变更范围时会说明 | 简短任务边界与完成条件 | SPEC-AGENTS 的 plan 适配 | 注入目标歧义或范围变化，检查是否暴露 |
| PC-G2 用对规范 | 当前相关的约定得到遵守，Agent 能自主调查 | 上下文选择与规范定位 | project-memory 的按职责读取，结合任务适配 | 检查相关约束是否被选中，普通小任务是否保持轻量 |
| PC-G3 核验交付 | 可以看见哪些条件满足、依据是什么、哪里没验证 | 结果与实际证据对应 | Superpowers 的 verification 适配 | 检查不相关的通过记录是否会被误用 |
| PC-G4 复用知识 | 下次工作能接上，并分清事实、推断、决定与未知 | 候选、来源、scope、冲突与准入 | project-memory 的知识维护适配 | 换上下文处理后续问题，检查误用与复核行为 |
| PC-G5 帮助人理解 | 人能找到行为、影响、未知和证据 | 基于同一知识来源的解释与资料 | technical-writer 的来源与读者目的适配 | 生成互补材料，再记录真实读者的维护判断 |

一个 [项目 Skill](../../skills/project-cognition/SKILL.md) 按任务读取相应组件。组件实际作用是给出输入、输出和关键判断边界；调查步骤、实现方法和资料形式仍由 Agent 决定。接入和上游差异见 [采用说明](../implementation/skill-composition.md)。

例如，维护者希望调整某段输出逻辑。Agent 先明确期望行为和必须保留的约束，调查实际路径，按完成条件说明方案及证据。随后只留下后续仍有用的关系、决定和未知；维护者可以用这些知识生成的说明或流程理解改动影响。

普通局部任务可能只需要目标和核验两部分。复杂任务才保留可交接材料；没有可复用发现时不必更新知识，没有读者问题时不必额外生成资料。

PC-V1 要求分别检查“文件存在”“Skill 做出了正确判断”“新上下文正确复用”“真实读者理解”和“投入产出更好”。任何一项的通过都不自动证明其他项。
