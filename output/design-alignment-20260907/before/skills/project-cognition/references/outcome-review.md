# 结果核验

改编自 Superpowers `verification-before-completion` 的结论与证据对应方法，并采用项目结果契约的范围与核验者区分。版本见 [来源清单](../THIRD_PARTY_NOTICES.md)。

## 对照完成条件

先读取原始任务和已确定的完成条件。对重要条件逐项指出实际产物或执行证据，打开并检查来源，记录 `满足 / 不满足 / 尚未验证`，以及核验者、核验方法和理由。

核验包含目标是否命中、适用规范是否遵守、证据是否支持结论强度、影响和未知项是否充分。对普通局部任务可以在几句话内完成。

## 证据要证明对应的事情

| 声明 | 所需证据 |
| --- | --- |
| 文件已修改 | 当前文件或实际 diff |
| 检查通过 | 相关命令、退出结果、所查 revision 或内容摘要及环境 |
| 原问题已解决 | 原问题触发路径的行为验证；修复任务应有能揭示原缺陷的回归证据 |
| 满足需求 | 完成条件逐项与行为、产物和证据对应 |
| 没有发现某问题 | 实际调查范围与未覆盖部分；局部搜索只支持局部结论 |
| 设计可实施 | 来源支持的边界、方案、约束与验证计划；实施和运行效果另行核验 |
| 用户接受或觉得有用 | 用户对相应结果的明确反馈 |

命令退出成功本身不证明业务条件满足。核验命令或检查方法必须有能力识别该条件不满足的情况；根据任务选择范围相称的检查，不用全面测试的形式替代相关性。

优先使用对当前相关内容和环境仍适用的执行证据。复用已有证据时注明实际执行者、基点和本次如何核对；没有本次运行就不称为本次复跑。只有内容、环境变化或存在未解决疑问时补充运行，不因开始新一条消息就机械重复整套测试。

## 分开报告状态

执行者的完成声明、模型自查、独立核验、知识接纳、资料生成和真实读者使用分别报告。文件存在、格式检查通过或模型模拟回答不能替代真实读者验收。

证据不足时给出局部结论或尚未验证项。需要更改目标、规范或风险接受时，把具体命题交回用户；不要修改验收标准来迁就已经产生的结果。
