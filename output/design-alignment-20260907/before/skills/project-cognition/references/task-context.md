# 任务与上下文

改编自 SPEC-AGENTS `plan` 的需求、未改变基线、事实与决定分工、轻量任务验收约定；知识定位参考 project-memory 的按职责读取。版本见 [来源清单](../THIRD_PARTY_NOTICES.md)。

## 形成当前任务的共同理解

保留用户原始请求或可靠引用。只明确会影响当前工作的内容：

- 要产生什么结果；
- 范围、必须保留的行为和明确排除的改动；
- 怎样判断完成，以及证据从哪里取得；
- 相关项目规范、已确认决定和重要未知；
- 哪些是 Agent 的解释或建议，哪些已经由用户决定。

小任务可以用一句验收与一句约束表达，不要求建立规格文件。较长任务把这份共同理解保存在已有任务落点，供下一次上下文恢复。任务完成条件先于结果评审建立，调整时记录理由和必要的确认。

## 选择上下文

从项目入口和现有知识索引寻找当前目标、规范、事实、决定、风险及未知项。保留每项知识的来源、状态和 scope；先读与当前任务直接相关的部分，需要时再追到源码、测试、配置和历史。

实际代码回答“怎么实现”；已确认决定回答“为什么选择”；测试和运行记录回答“在什么条件下观察到什么”。历史日志与生成资料用于定位，发现与来源不一致时追到相应 owner。

## 处理不确定性

可以通过工具查明的事实直接调查。缺失的是价值取舍、目标或授权时，提供具体影响和可选择的方案，让用户决定；独立工作继续进行。

已有授权范围内的调查、实现和核验直接推进。上游 `plan` 的逐轮确认、固定状态树和六动作路由在本适配中不自动启用。授权、知识准入和最终效果验收分别判断。
