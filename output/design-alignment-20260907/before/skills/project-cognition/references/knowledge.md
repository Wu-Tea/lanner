# 知识维护

改编自 project-memory 的 canonical home、按变化路由、事实与假设区分和 promotion 规则。版本见 [来源清单](../THIRD_PARTY_NOTICES.md)。长期知识位置由 [项目绑定](workspace-binding.md) 确定。

## 从任务发现形成候选

只保留后续任务或读者仍会需要的新增事实、修正、风险、决定、重要未知和关系。没有增量时明确无增量即可。当前任务结果保存完整答案，Delta 只描述候选变化。

每项候选应能说明：稳定 topic 或 ID、命题、scope、知识种类、来源及其 revision 或摘要、推断依据或确认记录、证据局限，以及会使其失效的变化。既有记录的修正还引用所基于的 Base revision 和旧 ID。

## 准入与确认

区分“跨任务有用”与“人类已确认”：有来源的解释可以按项目规则以 `inferred` 保存，始终保留推断状态。它不会因为重复出现、进入 Base 或被写成流畅文章就变成事实。

代码/配置支持实现事实，实际运行支持相应条件下的观察，用户确认支持特定目标或取舍。目标、规范、架构取舍和风险接受使用对应命题的明确人类确认。实现授权和上游作者的推荐都不能替代该确认。

只有项目已有规则允许的事实登记和资料重建才按该规则自动执行。没有明确准入规则时先保留 candidate；不建立默认自动接受规则。

## 冲突、过期与并发

比较 topic、scope、value、authority 和已有 supersede 关系。不同环境的不同值可以同时成立；确认同一范围内值不兼容后再记录冲突。

修改 Base 前重读当前基点。候选基点已改变时重新比较相关记录；重叠且不兼容的修改保留为待解决冲突。采用新值时保留旧版本或 supersede 路径及依据。

来源 revision、环境、依赖或证据变化时标明需要重新核验。没有查到内容与已证明不存在保持区分。历史记录只保留其原有范围，新的证据不追改过去的观察。

## 写到正确的位置

Base 保存可复用知识及来源索引；decision 保存确认与理由；Task Result 保存当前交付；handoff 保存接续游标；session log 保存历史事件；人类资料从 Base 派生。

只更新职责发生变化的文件。现有同名文档继续由原 owner 维护，不运行上游初始化器建立另一组 `CURRENT_STATE.md`、`ROADMAP.md` 或 `HUMAN_BRIEF.md`。这些上游角色在项目绑定中映射到已有落点。

长期保存前清理凭据、私人对话和无关个人信息。来源引用保留支持命题所需的粒度。
