# 案例分析与当前目标

当前案例分析引用 [BASELINE-2026-09-07-001](../../.agent-context/baselines/BASELINE-2026-09-07-001.md)。用户要求在提供案例前完整记录目标；目前尚未收到该案例，没有建立实际案例条目。

本目录保存用于理解或验证 Project Cognition 的案例材料与分析。案例是有自己来源和适用范围的研究对象；产品目标、规范与设计状态由相应正式文档和决定维护。完整依据见 [DEC-2026-09-07-005](../../.agent-context/decisions/DEC-2026-09-07-005-pre-case-baseline-and-scope-separation.md)。

## 收到一个案例时

按实际日期与顺序创建 `docs/cases/<case-id>/analysis.md`，例如 `CASE-YYYYMMDD-001`；名称只是记录约定，尚无固定产品 Schema。直接按用户要研究的问题调查并记录，不要求用户先填写表单。

一份案例记录按需要包含：

| 内容 | 记录要求 |
| --- | --- |
| 原问题与来源 | 用户希望案例说明什么；来自哪个项目、材料或运行；必要的 revision、环境和调查范围 |
| 参照基线 | 本次使用哪个 BASELINE；不能把分析之后的结论倒写成分析之前的目标 |
| 已知情况 | 分别标明用户报告、实际观察、Agent 推断与未知；每个重要结论给出来源 |
| 与产品的关系 | 对应 PC-G0–PC-G5、薄治理原则、传播或维护负担中的什么问题 |
| 观察与局限 | 当前证据支持什么、不足以判断什么；尝试、结果与原因推断分开 |
| 待修订建议 | 若涉及目标、scope、完成条件、规范或架构，列出原条目、建议变化、理由、影响与确认状态 |
| 下一动作 | 案例中尚需调查或由人决定的内容；实施工作是否已获授权 |

案例中的业务目标、约束、工具入口、AGENTS/README 内容和技术选择按案例来源及 scope 理解，不自动成为 Project Cognition 的新要求。引用代码或材料时保留来源；仅记录与问题有关的内容，避免持久化凭据、完整私人对话和无关个人信息。

## 案例怎样影响产品

事实核对、补证、纠错和案例内分析可以直接推进。有价值的观察先保存为案例结论或修订候选；一次成功不能推出普遍有效，一次局部失败也要先核对原因和适用范围。

涉及产品目标或已确认规范的变化，明确对应命题与 scope，取得相应用户确认后更新正式文档和决定，再生成新基线版本。用户已经明确给出的修改指令按其范围执行，不重复询问。旧基线保留，案例记录补充最终去向与决定链接。

若案例揭示真实遗漏、错误假设或目标冲突，要清楚报告并提出建议。保存基线用于追溯变化，不限制根据新证据修正方向。
