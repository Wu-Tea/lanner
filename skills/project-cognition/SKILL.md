## 开始当前工作

沿宿主的项目入口恢复当前任务，再确定本次需要的模块。原始用户请求是任务输入；已经给出的授权继续有效。Agent 自主选择调查、规划、工具和验证方法。

| 当前需要 | 读取 |
| --- | --- |
| 判断目标、范围、完成条件，选择相关事实与规范 | [任务与上下文](references/task-context.md) |
| 核验交付、审查结论或报告完成状态 | [结果核验](references/outcome-review.md) |
| 保留发现、恢复可靠知识、处理冲突或过期内容 | [知识维护](references/knowledge.md) |
| 解释项目、写人类资料、画流程或局部关系 | [人类资料](references/human-material.md) |

只有当任务需要某模块时才读取它。首次在项目中使用时，按 [项目绑定](references/workspace-binding.md) 找到现有知识、决定和证据的落点。一个模块的完成不自动触发其他模块。

## 按任务规模使用

普通局部任务在当前回答中简短说明预期变化、适用约束和验证结果。没有长期增量时，知识与人类资料都可以不更新。

跨会话工作、结构性变更或正式评审，保留可接续的任务目标、范围、完成条件和关键来源；收尾时将重要完成条件对应到实际证据。资料的形式、数量和篇幅由读者问题决定。

只在缺失信息会实质改变目标、边界、验收或权限时请求用户输入。可从仓库调查的事实由 Agent 查证。建议改变既定目标或受保护决策时，先解释影响并取得对应确认。

## 一次工作要交付的结果

- 任务：原始请求与解释后的目标可以比较，重要解释对用户可见。
- 交付：重要完成条件有证据、核验方法、实际判定和未验证项。
- 知识：需要保留的发现带来源、范围和状态，候选与接纳分开。
- 资料：使用同一知识读取基点，保留证据入口；人类使用效果单独记录。

结果形式可以是自然语言。只有长期保存或跨上下文交接确实需要时才落盘。现有项目契约和用户明确要求优先于本包的示例、默认位置及上游习惯。

## 确认与证据

用户对目标、规范、架构取舍或风险接受的确认，只作用于被确认的命题和范围。允许实施一个方案不等于已经认可其效果，也不等于批准它成为长期规范。引用上游 README 只能证明其公开描述，运行效果需要对应运行证据。

来源、范围或状态变化后重新检查相关知识。模型自查、独立模型检查、合成场景和真实用户验收分别标明。
