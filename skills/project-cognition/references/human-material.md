# 人类资料

> 未采纳草稿；仅供设计审阅，未安装或运行。以下描述不是当前工作指令，状态见 [草稿入口](../SKILL.md)。

改编自 technical-writer 的读者目的、文档类型、来源与事实唯一归属规则；方向来自本项目的人类资料契约。版本见 [来源清单](../THIRD_PARTY_NOTICES.md)。

## 从读者的实际问题开始

明确读者已经知道什么、这次要判断什么、关注哪个行为或对象。先解释用途、输入、输出和运行边界，再以一条完整行为引入模块、机制和关系。

资料不是必交模板。普通任务可以直接回答；需要让人持续使用时再保留文章、流程、局部关系或证据详情。选择能回答当前问题的形式，保持焦点和返回来源的路径。

## 共享知识基点

current 资料使用同一 Base 读取基点和已确认的语义，不把未接纳候选混入正文。候选只能形成明显标注的 preview；已保存的 inferred 知识继续作为有标记的解释展示，不借生成动作升级其状态。

每份持久化资料记录 Base revision、所用记录 ID 和来源入口。相同命题在不同形式中使用相同 ID、scope 和来源。图中的节点、箭头、方向与条件和文字一样需要依据；不存在的关系不因画图需要而补出。

发现新事实或读者提出语义修正时形成 Knowledge Delta，经过项目准入后更新 Base，再重建相关资料。纯粹版式、用词和导航改进可以直接修订投影。

## 按文档职责修改

- 规范性资料：说明已确认要求；实现偏离时报告偏离。
- 行为说明：与其来源所证明的行为一致；候选实现使用提案状态。
- 历史与决定：保留原记录，使用新记录修正或 supersede。
- 操作说明：区分已运行的步骤与尚未试用的计划。
- 索引：指向 owner，不替代 owner 决定事实。

## 验证是否有用

选择一个维护问题，检查资料是否帮助读者定位影响、重要未知和待决定项，并返回证据。记录真实回答、需要补充解释的地方和可获得的阅读成本。

模型扮演读者时标为合成评估。生成成功与真实理解分开，没有真实反馈时不报告读者已接受。

上游固定字数、英语禁用词、强制文档家族、固定画图工具和禁止源码关系图等作者偏好不作为本项目要求。表达由当前读者、语言、问题和项目契约决定。
