# 检查三台设备，先去哪一台？

假设学校要安排人查看几台水泵有没有漏水、声音是否正常。按安排去查看设备并记录结果，叫“巡检”。这个 Demo 是一个能运行的小程序：你选中要检查的设备，它给出几个先后顺序，让你看到程序是怎样计算的。

设备、位置和过去的检查数据都是专门编造的，打开页面即可使用，不需要配置数据库。

## 先打开，再跟着一个例子看

解压后双击同一目录下的 `index.html`。浏览器会打开页面；这一步不需要安装 Node.js，也不需要运行命令。

页面默认选中了 8 台设备。第一次只保留设备 01、02、05，并把起点选为设备 01，点击“生成候选路线”。图上的连接表示去这些设备的先后顺序，不是现场能走的道路。

如果不明白它为什么这样算，先读同一目录下的 [入门说明 guide.md](guide.md)。它从设备表、检查对象表怎样通过编号关联讲起，再用两层循环、二维数组和一个可以手算的例子讲完整过程。你不需要提前学过巡检业务或寻路算法。

## 页面上的数据和名字是什么意思

“检查对象”就是这次要去检查的设备记录。“合成数据”表示这些资料是编造的。页面中的设备编号、坐标、楼栋、楼层和房间都来自 `fixtures.js` 文件；其中的位置用于计算两台设备之间的距离。

“候选路线”就是留着比较的一种检查顺序。三台设备，从 01 开始，可以尝试 01→02→05，也可以尝试 01→05→02；不是每一种尝试都一定不同。

“计算过程”里用到的“矩阵”，是把每两个设备之间的数值按行列放在一张表里，代码里用二维数组保存。读一格时，先看行标题“从谁出发”，再看列标题“去谁那里”。

程序先按距离算一个数值，再因为同楼、同层、同房间或过去经常相邻而减去一些数值。用于影响选择的这些数值叫“权重”。同一行同一列的计算是：距离数值减去空间奖励，再减去历史边权。“空间奖励”就是同楼等条件要减的值，“历史边权”就是过去检查顺序要减的值。

因此，合并表里出现 −12 这样的数字并不表示距离为负，它只是比较选择时用的分数。最后显示的路程还要根据排好的设备顺序重新相加。

## 怎么看出某项数据有没有用上

先在“合成数据”里查看设备的位置资料，再到“计算过程”的下拉框里切换四张表：距离矩阵、空间奖励、历史边权、合并权重。对照同一格，看相减是否能得到最后的值。

然后取消“考虑楼栋、楼层与房间”或“考虑合成历史偏好”，再计算一次，比较表中的数值。输入改变后，最后的顺序不一定变化；先看对应分数有没有变化更容易理解。

“请求与响应”里，左边是传给方法的参数，右边是方法返回的数据。你可以直接修改左边的 JSON，再点击“用这个请求计算”。

## 两种模式怎样理解

“原逻辑移植”是把原 Java 的处理步骤改写成浏览器能执行的 JavaScript。它保留了原代码的问题，包括距离计算问题和第二条路线的距离随机改写。

例如，第二条本来有自己的计算距离，原代码却把它改成第一条的约 92%–98%，没有跟着重算预计时间。所以这里不能把页面的“最短路线”标签理解成已经证明它最短。

“距离校正对照”调整距离计算和相关显示，让你比较这个问题的影响；挑选检查顺序的方法仍然相同。`eta` 是预计耗时，单位为秒。两种模式都没有道路、围墙、楼梯的数据，不能代替现场导航。

## 想从代码调用这个方法

只体验页面可以停在上面。想发 HTTP 请求时，需要安装 Node.js 18 或更高版本，它用于在电脑上运行这里的 JavaScript 服务程序。

在这个目录打开终端，运行 `node server.js`，或双击 Windows 的 `start.cmd`。看到启动提示后，访问 `http://127.0.0.1:4173`。`127.0.0.1` 表示你自己的电脑，`4173` 是这个程序使用的端口。按 Ctrl+C 可以停止服务。

不需要运行 `npm install`。如果 4173 已被其他程序占用，可以在 PowerShell 先运行 `$env:PORT='4174'`，再运行 `node server.js`，然后访问 4174 端口。

## 本地接口

```http
POST /api/inspect/line/recommend/list?mode=legacy&scenario=standard
Content-Type: application/json

{
  "objectIds": [1,2,3,4,5,6,7,8],
  "smx": "10.0005",
  "smy": "20.0005",
  "startObjectId": 1
}
```

`mode` 为 `legacy` 或 `corrected`；`scenario` 为 `standard`、`large`、`single` 或 `missing`。通过查询参数 `history=off`、`spatial=off` 分别关闭历史或空间权重。未提供参数时默认原逻辑、基础场景并启用两种权重。

响应保留 `success`、`code`、`message`、`result`；路线结果保留 `pathNodes`、`totalDistance`、`eta`、`name`、`type`。额外的 `demo` 包含警示、矩阵和每条结果的原距离、改写比例、候选排序及逐段数据。它是演示解释字段，不是原服务契约。

可用 PowerShell 调用：

```powershell
$body = @{ objectIds=@(1,2,3,4,5,6,7,8); smx='10.0005'; smy='20.0005'; startObjectId=1 } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:4173/api/inspect/line/recommend/list?mode=corrected' -Method Post -ContentType 'application/json' -Body $body
```

## 与原实现的关系

本演示是原 Java 业务算法的独立 JavaScript 移植，未启动 Spring、数据库、Redis、RabbitMQ 或资产服务。

| 范围 | 保留或变化 |
| --- | --- |
| 对象与资产查询 | 用固定的合成 fixture 替代；对象按 fixture 顺序查询，不承诺按请求 ID 排序 |
| 历史查询 | 输入合成的聚合 EdgeWeight；不模拟原 SQL 的采样、事务和排序问题 |
| 原逻辑模式 | 保留原距离公式/参数顺序、矩阵缩放、逐级空间奖励、有向历史权重、减法合并、-1000 起始边和优先队列展开 |
| 候选展示 | 保留首条、第二条、第 10 条或末条选择；原逻辑保留路线2随机显示与原 ETA 不重算行为 |
| 数字精度 | JavaScript Number，模拟关键舍入步骤；不承诺与 Java BigDecimal 每一位相同或所有并列排序完全一致 |
| 对照模式 | 只校正距离单位/坐标顺序、ETA 和随机显示；候选搜索策略不变，不宣称全局最优或生产修复 |
| 输入边界 | 演示新增类型、长度、重复、未知对象、起点及坐标校验；空列表直接返回空结果；和原异常/默认行为不同 |
| 执行模型 | 本地同步计算；未复现 Java Future、线程上下文、超时、实际数据库或外部服务错误 |

`engine.js` 导出 `recommendLines(objectIds, smx, smy, startObjectId, data, options)`，便于独立调用；`run(query,data,options)` 额外返回完整解释信息。模式与 fixture 来自服务端允许的列表，服务不会读取任意本地文件。

## 数据脱敏方式与交付边界

采用**完整合成替代**，没有读取真实数据库再做可逆替换。ID 从 1 开始；资产 ID 为独立演示编号；名称为设备 NN；空间为 A/B/C 区及虚构房间；坐标由示意位置独立生成；历史权重人工构造。它保留计算需要的结构，不能保留或证明真实业务分布。
